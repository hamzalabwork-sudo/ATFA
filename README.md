# ATFA — Adaptive Trust for Financial Autonomy

Code, benchmark generator, configurations and results for the paper
**"ATFA: Adaptive Trust for Financial Autonomy in Blockchain-Settled Industrial IoT Payments"**.

ATFA is a pre-settlement authorisation framework for IoT-triggered payments. For every claim produced by
a connected asset (e.g., operating hours reported by leased industrial equipment), ATFA

1. checks hard security rules (signature, replayed sequence number, timestamp window, contract cap),
2. scores the telemetry with a **TCN + XGBoost** anomaly detector using cross-channel and long-horizon features,
3. updates an **adaptive Beta trust** of the device (asymmetric evidence + feedback from verified claims),
4. computes the risk `R = 1 - T (1 - s)` and decides **APPROVE / HOLD / REJECT** with thresholds calibrated to
   minimise the fraudulent value settled under budgets on delayed (≤ 5 %) and refused (≤ 1 %) legitimate claims,
5. anchors a SHA-256 commitment of every decision on **PureChain PoA²**; only claims anchored as approved are settleable.

```
device report ─► hard rules ──────────────────────────────────────────► REJECT
      │
      ├─► TCN+XGBoost anomaly score s ─┐
      └─► adaptive trust T (read before update) ─► R = 1 − T(1 − s) ─► APPROVE / HOLD / REJECT
                                                        │                     │
                         evidence digest anchored on PureChain ◄──────────────┘
                         settlement only if isSettleable(digest)      HOLD → verification → trust feedback
```

## 1. Installation

Tested on Windows 11 with Python 3.14 (CPU only; no GPU required). Any Python ≥ 3.11 should work.

```bash
git clone https://github.com/hamzalabwork-sudo/ATFA.git
cd ATFA
python -m venv .venv
# Windows:      .venv\Scripts\activate
# Linux/macOS:  source .venv/bin/activate
pip install -r requirements.txt
python -m pytest -q tests          # 18 tests: leakage guard, invariants, policy guarantees, ledger, loaders
```

All experiments are seeded and deterministic: re-running a configuration reproduces identical numbers.

## 2. Datasets

### 2.1 ATFA-AssetFinance (generated by this repository — no download needed)

Public IoT intrusion datasets contain no ground truth for equipment usage or payment amounts, so the
financial evaluation uses a reproducible benchmark generated by `atfa/generator.py` from the parameters in
`configs/default.yaml`.

| Property | Value |
|---|---|
| Application | usage-based industrial equipment leasing; one report per asset per day; a report with hours > 0 is a payment claim |
| Fleet | 100 assets, 10 sites, 4 equipment types, 730 days (≈ 49,000 claims per fleet) |
| Telemetry | reported hours, independent hour meter, fuel, RPM, engine temperature, vibration, idle time, ambient temperature, sequence number, timestamps, signature |
| Benign faults | sensor noise, dropouts, stuck sensors, delayed / out-of-order messages, clock drift, overtime, maintenance |
| Attacks | inflation, replay, forged identity, gradual compromise, on-off; naive / consistent / adaptive attackers |
| Compromise levels | 5, 10, 20, 30 % of assets (after a 120-day attack-free commissioning period) |
| Ground truth | true hours, anomaly/fraud labels, attack family — in evaluator-only columns never read by the pipeline |

**Export it as CSV** (e.g., to inspect it or to use it with other methods):

```bash
# one fleet: 20 % compromised, seed 20 (a confirmatory seed)
python scripts/generate_dataset.py --seed 20 --level 0.20 --out data/atfa_assetfinance

# all confirmatory in-distribution fleets (80 fleets)
python scripts/generate_dataset.py --seeds 20-39 --levels 0.05,0.10,0.20,0.30 --out data/atfa_assetfinance
```

Each fleet produces `<name>_observable.csv` (model inputs), `<name>_groundtruth.csv` (labels; aligned on
`asset_id, day`) and `<name>_assets.csv` (asset/contract metadata), plus `DATA_DICTIONARY.md` describing
every column. Inside Python:

```python
from atfa.config import load_config
from atfa.generator import generate_world
cfg = load_config("configs/default.yaml")
g = cfg["generator"]; g["compromise_fraction"] = 0.20
records, assets = generate_world(g, seed=20)      # pandas DataFrames
```

Seeds used in the paper: **20–39** confirmatory in-distribution, **20–24** each distribution-shift scenario,
**40–44** robustness, **0–9** first (v1) evaluation, **100–105** design development only.

### 2.2 TON_IoT telemetry (download)

Used to validate the detectors on real IoT telemetry (7 device streams).
Source: UNSW Canberra, official page <https://research.unsw.edu.au/projects/toniot-datasets>
(Alsaedi et al., IEEE Access, 2020). We used the complete processed IoT streams
(`Processed_IoT_dataset/IoT_*.csv`), which are also mirrored on Kaggle as `medworldmed/ton-iot-datasets`
(record counts match the original publication, e.g. 587,076 fridge readings).

```bash
pip install kagglehub
python -c "import kagglehub; kagglehub.dataset_download('medworldmed/ton-iot-datasets', output_dir='data/ton_iot')"
# expected: data/ton_iot/Processed_IoT_dataset/IoT_{Fridge,Garage_Door,GPS_Tracker,Modbus,Motion_Light,Thermostat,Weather}.csv
```

### 2.3 Edge-IIoTset (download)

Used for network-level detection. Source: Ferrag et al., IEEE Access, 2022; Kaggle
`mohamedamineferrag/edgeiiotset-cyber-security-dataset-of-iot-iiot`. Place the ML subset at
`data/edge_iiotset/ML-EdgeIIoT-dataset.csv` (the DNN subset also works). Label-leaking identifier and payload
fields are removed and duplicates are dropped automatically by `atfa/public.py`.

## 3. Reproducing the paper

`bash reproduce.sh` runs everything in order (≈ 10 h on a 12-thread CPU); `bash reproduce.sh quick` is a
≈ 20 min smoke run. Individual steps:

| Paper result | Command | Output |
|---|---|---|
| Window length selection | `python scripts/select_window.py --models tcn,lstm` | `results/window_selection.csv` |
| **Main confirmatory results** (detection, financial protection, distribution shift, trust, ablation, statistical tests) | `python scripts/run_experiments.py --config configs/confirmatory_v2.yaml --out results/confirmatory_v2`, then `python scripts/make_report.py --results results/confirmatory_v2` | `results/confirmatory_v2/report/` |
| Cost-parameter sensitivity | `python scripts/cost_sensitivity.py --results results/confirmatory_v2` | `results/confirmatory_v2/report/cost_sensitivity.md` |
| Parameter sensitivity | `python scripts/run_experiments.py --config configs/cache_confirmatory.yaml --out results/sensitivity_v2`, then `python scripts/param_sensitivity.py` and `python scripts/make_sensitivity_figure.py` | `results/sensitivity_v2/` |
| Robustness (harsher noise, 500-asset fleet) | `python scripts/run_experiments.py --config configs/robustness_v2.yaml --out results/robustness_v2` | `results/robustness_v2/` |
| TON_IoT | `python scripts/run_public.py ton_iot --data data/ton_iot/Processed_IoT_dataset --out results/public_v2 --protocols blocked --workers 4` | `results/public_v2/` |
| Edge-IIoTset | `python scripts/run_public.py edge_iiot --data data/edge_iiotset/ML-EdgeIIoT-dataset.csv --out results/public` | `results/public/` |
| Computational overhead | `python scripts/bench_decision.py --out results/overhead` | `results/overhead/` |
| PureChain measurements | see Section 4 | `results/purechain/` |
| First (v1) evaluation and v2 development (history) | `configs/default.yaml`, `configs/dev_v2.yaml`, `configs/dev_cache.yaml` | `results/full/`, `results/dev_v2/`, `results/dev_cache/` |

Each run writes one JSON file per simulated fleet to `<out>/worlds/` and resumes automatically if
interrupted; `--merge-only` rebuilds the CSV tables. Inspect a single fleet with
`python scripts/debug_world.py --scenario id --level 0.2 --seed 20`.

**Verifying without re-running:** all per-fleet results used in the paper are included under
`results/*/worlds/` and the merged tables under `results/*/*.csv`; `make_report.py` regenerates every table
and figure from them in seconds.

### Configuration

All parameters are in `configs/default.yaml` (generator, splits, detectors, trust, authorisation, costs);
experiment configs inherit from it via `base:`. The final ATFA design is fixed in the `atfa_design` block.
Development worlds (seeds 100–105) were used to choose the design; the plan for the confirmatory evaluation
was fixed beforehand in `docs/confirmatory_plan.md`.

## 4. PureChain PoA² (optional; requires network access)

The anchoring contract `contracts/ATFAEvidenceAnchor.sol` is deployed on the live PureChain network
(chain ID 900520900520, RPC `https://purechainnode.com`) at
`0x6592cBD3CE1303EAfBfDE9f65301DD428844Ed5E` (`deployments/purechain.json`).

PureChain uses a zero gas price, so a freshly generated key can transact without funds. To reproduce the
measurements with your own deployment:

```bash
python scripts/purechain_deploy.py --admin <your-admin-wallet-address>   # creates .env with a new key, deploys, runs on-chain checks
python scripts/bench_ledger.py --adapter purechain --out results/purechain          # latency, batching, load, settlement check
python scripts/purechain_bench_setup.py --accounts 4                                 # benchmark instance with 4 authorisers
python scripts/bench_ledger.py --only E5 --out results/purechain                     # per-sender scaling
PYTHONPATH=scripts python scripts/make_ledger_report.py --results results/purechain
```

Private keys are written only to `.env`, which is git-ignored; never commit it. On networks that intercept
TLS, the code uses the operating-system trust store (`truststore`).

## 5. Key results (confirmatory evaluation, fresh seeds)

| | Result |
|---|---|
| Fraudulent value prevented | **95–97 %** (holding ≤ 5 % and rejecting ≤ 1 % of legitimate claims), vs 39–45 % for a fixed amount threshold and 0 % for a plain smart contract |
| Best detector | TCN+XGBoost ensemble, PR-AUC 0.860, best of 8 detectors in all 9 scenarios |
| Adaptive trust | 67 % of compromised devices reach low trust (Beta reputation: 19 %); no honest device falsely flagged |
| Robustness | holds across 21 parameter settings, 20 cost models, harsher sensor noise and a 5× fleet |
| Public data | TON_IoT ROC-AUC up to 0.944; Edge-IIoTset F1 0.986 |
| PureChain | median confirmation 1.98 s; 24.1k gas/record batched; no lost transactions |
| Overhead | 4.1 ms per claim (one CPU thread); 0.8 MB of models; 3.3 KB state per asset |

Full tables: `docs/results_summary_v2.md`.
